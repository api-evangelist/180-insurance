- [Efetuar cotações.](https://docs.180s.com.br/reference/post_sagas-v1-cotacoes.md): Endpoint usado para cotar o seguro de acordo com o risco informado e coberturas escolhidas.    Para criação de um proposta será necesário informar o ID de um **Combo de Produto** e o ID de um **Produto**, ambos podem ser obtidos através da rota **/sagas/v1/combos**.    O campo <b>metadados</b> segue o formato de chave/valor e serão anexados junto à cotação.    Sendo assim, esse campo poderá ser utilizado para armazenar quaisquer informações que forem relevantes para sua operação.
- [Obter detalhes de uma cotação.](https://docs.180s.com.br/reference/get_sagas-v1-cotacoes-id-cotacao.md): Endpoint utilizado para retornar os detalhes de uma cotação através do seu ID.
- [Listar produtos e cotações.](https://docs.180s.com.br/reference/post_sagas-v1-combos-com-cotacao.md): Endpoint usado para buscar os dados de um produto e suas respectivas cotações.
- [Criar propostas.](https://docs.180s.com.br/reference/post_sagas-v1-propostas.md): Endpoint usado para realizar a emissão de uma proposta.    Para realizar a emissão de uma proposta será necessário informar o ID de uma cotação.    Uma proposta emitida poderá estar nos seguintes status:    **Pendente**: Ocorre quando existem alguns requisitos que ainda não foram preenchidos para que a proposta seja concluída. Exemplo: Pagamento da proposta ainda está pendente.    **Completa** Quando não existem pendências atreladas a proposta. Nesse status automatiacmente será criada uma **venda** e consequentemente a emissão da apólice de seguro.
- [Obter detalhes de uma proposta.](https://docs.180s.com.br/reference/get_sagas-v1-propostas-id-proposta.md): Endpoint utilizado para retornar os detalhes de uma determinada proposta.
- [Atualizar uma proposta existente.](https://docs.180s.com.br/reference/patch_sagas-v1-propostas-id-proposta.md): Endpoint utilizado para atualizar uma proposta existente.
- [Solicitar cancelamento de proposta por id](https://docs.180s.com.br/reference/post_sagas-v1-propostas-id-proposta-solicitar-cancelamento.md): Endpoint utilizado para cancelar uma proposta.    Para que seja possível cancelar uma proposta, a mesma deve estar no status `pendente`.
- [Obter documento referente à proposta.](https://docs.180s.com.br/reference/get_sagas-v1-documentos-propostas-id-proposta-produtos-id-produto.md): Obter o documento de uma proposta gerada.    A resposta desse endpoint será em um formato de documento, contendo o header `Content-type: application/pdf`.
- [Atualizar dados do cliente-segurado (proposta pendente)](https://docs.180s.com.br/reference/patch_sagas-v1-propostas-id-proposta-cliente-segurado.md): Endpoint que permite atualizar dados do cliente segurado enquanto a proposta está pendente. Alterações em uma proposta completa são feitas por endossos na venda correspondente.
- [Reenviar uma comunicação de proposta](https://docs.180s.com.br/reference/post_sagas-v1-propostas-id-proposta-reenviar-comunicacao-comunicacao.md): Endpoint que permite reenviar uma comunicação de proposta (como termos e condições), quando aplicável
- [Obter boleto.](https://docs.180s.com.br/reference/get_sagas-v1-boleto-payment-intent-id.md): Redireciona (302) para a URL pré-assinada do PDF do boleto.
- [Listar vendas de um cliente.](https://docs.180s.com.br/reference/post_sagas-v1-vendas.md): Endpoint utilizado para listar as vendas atreladas a um determinado cliente.
- [Obter venda específica e entidades relacionadas.](https://docs.180s.com.br/reference/get_sagas-v1-vendas-id-venda.md): Endpoint utilizado para listar detalhes de uma venda específica.
- [Solicitar cancelamento de venda por id para um cliente.](https://docs.180s.com.br/reference/post_sagas-v1-vendas-id-venda-solicitar-cancelamento.md): Solicitar o cancelamento de uma venda. Será criada uma entidade chamada **cancelamento** que possui os seguintes status:    **Pendente**: Ocorre quando há alguma pendência na venda que impede o cancelamento imediato. Exemplo: O cancelamento foi agendado para uma data futura.    **Completo** Quando o cancelamento foi efetuado. Nesse status pode-se considerar que a apólice de seguros não está mais vigente.    Para casos em que for necessário o reembolso, será necessário informar os dados bancários do cliente para que seja feita a restituição.
- [Obter documento referente à venda](https://docs.180s.com.br/reference/get_sagas-v1-documentos-vendas-id-venda-produtos-id-produto.md): Obter certificado de venda emitido para o cliente contratante.    A resposta desse endpoint será em um formato de documento, contendo o header `Content-type: application/pdf`.
- [Solicitar alterações após venda concluída.](https://docs.180s.com.br/reference/post_sagas-v1-vendas-id-venda-alteracoes.md)
- [Abrir sinistro para apólice vinculada a venda.](https://docs.180s.com.br/reference/post_sagas-v1-vendas-id-venda-abrir-sinistro.md): **⚠️ Endpoint em desenvolvimento (WIP).** O comportamento e contrato podem sofrer alterações.  Realiza a abertura de um sinistro para a apólice de seguro vinculada a uma venda.  Para abrir o sinistro é necessário informar: - `pessoa-para-contato`: dados de quem a seguradora deve contatar - `solicitante`: identificação do solicitante do sinistro - `cobertura`: cobertura acionada (deve corresponder a uma cobertura ativa da apólice) - `data-aviso`: data na qual o segurado entrou em contato para ativação do sinistro - `data-ocorrencia`: data em que o evento ocorreu  Opcionalmente é possível informar `relato-do-ocorrido`, `saldo-devedor` e `detalhes-pagamento` (caso já se saiba beneficiário e método de pagamento).  O campo `natureza` é obrigatório para as coberturas `cobertura/morte` e `cobertura/perda-de-renda`. Os valores aceitos são: - `morte-acidental`: morte por acidente - `morte-natural`: morte por causas naturais - `perda-de-renda-desemprego`: perda de renda por desemprego - `perda-de-renda-invalidez-fisica`: perda de renda por invalidez física  O sinistro criado pode assumir os seguintes status: `criado`, `pendente-de-documentacao`, `em-regulacao`, `recusado` ou `finalizado`.  O campo `numero-sinistro` retornado é o identificador utilizado nos demais endpoints de sinistro.
- [Obter detalhes de um sinistro.](https://docs.180s.com.br/reference/get_sagas-v1-sinistros-numero-sinistro.md): **⚠️ Endpoint em desenvolvimento (WIP).** O comportamento e contrato podem sofrer alterações.  Retorna os detalhes completos de um sinistro a partir do seu número.  A resposta inclui: status atual, valor total aprovado (`valor`), valor restante a pagar (`valor-restante`), lista de pagamentos realizados (`pagamentos`), cobertura acionada, datas de aviso e ocorrência, dados do solicitante e da pessoa para contato.  Quando aplicável, a resposta também inclui: - `documentacao`: documentos solicitados e lista de arquivos enviados - `recusa`: motivo e data de recusa, caso o sinistro tenha sido recusado - `franquia-paga`: valor de franquia já pago pelo segurado - `natureza` e `relato-do-ocorrido`: detalhes narrativos do ocorrido
- [Gerar url para upload de documento de sinistro.](https://docs.180s.com.br/reference/post_sagas-v1-sinistros-numero-sinistro-enviar-documento.md): **⚠️ Endpoint em desenvolvimento (WIP).** O comportamento e contrato podem sofrer alterações.  Gera uma URL pré-assinada para upload de um documento vinculado ao sinistro.  Após receber a resposta, o cliente deve realizar o upload do arquivo diretamente na URL retornada no campo `url-envio` utilizando uma requisição **PUT**.  É necessário informar o nome do arquivo (`nome-arquivo`) e a data de envio (`data-envio`). Os campos `tipo` e `id-externo` são opcionais.
- [Baixar arquivo de documentação de sinistro.](https://docs.180s.com.br/reference/get_sagas-v1-sinistros-numero-sinistro-documentos-file-id.md): **⚠️ Endpoint em desenvolvimento (WIP).** O comportamento e contrato podem sofrer alterações.  Baixa o arquivo de documentação identificado por `file-id` vinculado ao sinistro.  A resposta é o conteúdo binário do arquivo com os headers `Content-Type` e `Content-Disposition` correspondentes ao arquivo original enviado.
- [Gerar URL de sinistro whitelabel.](https://docs.180s.com.br/reference/post_sagas-v1-sinistros-whitelabel-gerar-url.md): **⚠️ Endpoint em desenvolvimento (WIP).** O comportamento e contrato podem sofrer alterações.  Gera uma URL temporária para gerenciamento de sinistros via whitelabel.  A URL retornada expira conforme configuração do canal e deve ser usada dentro do período de validade.
- [Atualizar saldo devedor de um sinistro.](https://docs.180s.com.br/reference/post_sagas-v1-sinistros-numero-sinistro-saldo-devedor.md): **⚠️ Endpoint em desenvolvimento (WIP).** O comportamento e contrato podem sofrer alterações.  Atualiza o saldo devedor de um sinistro a partir do seu número.  O valor informado em `saldo-devedor` será utilizado para ajustar o valor do sinistro, respeitando o limite máximo de indenização da cobertura.  A resposta retorna o sinistro atualizado, incluindo `valor`, `valor-restante` e `saldo-devedor`.
- [Listar os produtos.](https://docs.180s.com.br/reference/get_sagas-v1-combos.md): Endpoint utilizado para listar os detalhes das configurações de produtos.
- [Listar assinaturas.](https://docs.180s.com.br/reference/get_sagas-v1-webhooks.md): Endpoint utilizado para obter os webhooks ativos e suas respectivas urls.
- [Criar nova assinatura para eventos.](https://docs.180s.com.br/reference/post_sagas-v1-webhooks.md): Endpoint utilizado para cadastrar uma url que será utilizada no envio de webhooks.    A url cadastrada deverá obrigatoriamente responder ao verbo POST e retonar o status da família 2xx (Exemplo: status 204).
- [Remover assinatura.](https://docs.180s.com.br/reference/delete_sagas-v1-webhooks-id-webhook.md): Endpoint utilizado para remover permanentemente uma assinatura de webhook.    Caso a assinatura seja removida através desse endpoint, não será possível mais reativá-la. Logo, será necessário realizar o cadastro de uma nova assinatura.
- [Atualizar assinatura.](https://docs.180s.com.br/reference/patch_sagas-v1-webhooks-id-webhook.md): Endpoint utilizado para atualizar as informações de uma assinatura de webhook.    Caso queira desativar o envio para uma determinada url temporariamente, basta utilizar este endpoint para atualizar o parâmetro `ativo` para `false`.
- [Rotacionar chave HMAC](https://docs.180s.com.br/reference/post_sagas-v1-webhooks-id-webhook-rotacionar-chave-hmac.md): Inicia processo para rotacionar chave HMAC da assinatura. A chave atual continua funcionando por 7 dias a partir da chamada deste endpoint. A nova chave retornada deve passar a ser usada dentro deste período.
- [Endpoint para iniciar uma renovação que está disponível.](https://docs.180s.com.br/reference/post_sagas-v1-renovacoes-id-renovacao-iniciar.md): Permite iniciar uma renovação que está disponível.  É possível usar uma cotação própria ou aceitar a sugerida pela cotação. Também é possível informar dados cadastrais do cliente, caso seja necessário. Pode ser necessário informar a forma de pagamento e aceite, conforme requerimentos do produto sendo renovado.
- [Obter detalhes sobre uma renovação.](https://docs.180s.com.br/reference/get_sagas-v1-renovacoes-id-renovacao.md)
- [Listar renovações.](https://docs.180s.com.br/reference/get_sagas-v1-renovacoes.md): Lista as renovações existentes.  Este endpoint possui paginação; confira a documentação em https://docs.180s.com.br/reference/paginação.
